# 定位与需求证据复审

面向"这个插件到底有没有人用、值不值得继续投入"的判断。数据来自 npm 官方下载统计（`api.npmjs.org/downloads/range`），取数日 **2026-11-11**，窗口为最近 30 天。

## 一、先说结论

1. **我们自己的下载量是自造噪声，不能当作需求证据。**
2. **至少两个同类插件有稳定的日活级下载**，这是真实的外部使用。
3. 因此：工程质量这一侧我们确实做到了"边界内很硬"，但**"独一档"在需求侧没有证据**——不能说，也不该说。

## 二、数据

### 我们的逐日曲线（最近 12 天）

| 日期 | 下载 |
|---|---|
| 10-29 → 11-06 | **0 / 0 / 0 / 0 / 0 / 0 / 0 / 0 / 0** |
| 11-07 | 1538 |
| 11-08 | 638 |
| 11-09 | 1182 |

前一个月**每天都是 0**，直到 11-07 突然出现三位数。而 11-07 到 11-09 正是我们密集发版（0.1.2x–0.1.3x）并反复安装到本机 profile 与 VM 的几天。今天（11-11）的数据尚未结算，而那十几次安装同样会进账。

**结论：这些下载来自我们自己的发布流水线与安装动作，不是用户。**

### 同类插件的逐日曲线（对照）

| 包 | 最近 10 天区间 | 形态 |
|---|---|---|
| `dsh-split-workspace` | 28 – 58 / 天 | 连续一个月每天稳定，**典型的自然使用** |
| `dsh-plugin-workspace-split` | 21 – 61 / 天 | 有一次性尖峰后回落到 20–60 |
| `dsh-call-session`（非同类，作基线） | 55 – 283 / 天 | 高基线，说明生态里有真实流量 |

这才是"有人在用"的形态：**没有尖峰、日复一日**。

## 三、这意味着什么

- **不能说"我们最受欢迎"**。按上一次 30 天总量看我们确实高于同类，但那是自造噪声；把它当卖点就是拿自己的 CI 当用户。
- **不能说"我们独一档"**。工程侧（验证深度、集成克制、键盘完整）可以逐条举证；需求侧没有证据。
- **市场评审的"能力最弱"判断仍然成立**：格数、格内预览、格内新建我们确实不做，这是刻意的边界，不是能力缺失，但需要用户看得到边界内的价值。

## 四、下一步的三个选项（成本从低到高）

| 选项 | 做法 | 成本 | 可能收益 |
|---|---|---|---|
| A. 提交市场条目 | 把 `data/plugins/Awenforever__dsh-multiview.yml` 提 PR 到 awesome-dsh-plugin | 低（已有草稿，且已按评审意见改过定位） | 让"存在"变成"可被发现"；这是唯一相对确定的获客动作 |
| B. 降低首屏门槛 | README 顶部放一张真实的四格截图 + 一段 15 秒操作动图 | 中（需要能跑起来截图，当前被 R31/R32 阻塞） | 分屏类插件靠"看起来好用"转化；纯文字转化率低 |
| C. 扩大能力边界 | 格内预览、更多格数等 | 高（与既有边界冲突，且会削弱集成克制） | 不确定；同类的稳定下载说明"能力多"不是唯一变量 |

**我的建议：先 A，再 B。** A 的投入最小，且能把"有没有需求"这个问题变成可观测的（市场条目的点击/安装转化）。C 在没有需求证据前投入，只是把工程优势换成更宽的战线。

## 五、数据取法（可复核）

```
curl -sS "https://api.npmjs.org/downloads/range/last-month/dsh-multiview"
curl -sS "https://api.npmjs.org/downloads/range/last-month/dsh-split-workspace"
```

注意：npm 的计数包含 CI、镜像与重复安装，因此**单点数字无意义，日曲线形态才有意义**（尖峰 = 自动化；平稳 = 使用）。这条判断标准本身就是本轮得出的。
