# 状态看板：0.1.29 – 0.1.59 到底变了什么

面向"要不要用/要不要继续投入"的判断，不是变更日志的复述。变更日志在 `CHANGELOG.md`，逐条可查。

## 一句话

从"能分屏"变成"**盯盘的专用工具**"：新增注意力路由（含侧栏徽标）、侧栏直接投放、命名布局库与键盘完整覆盖；同时修掉 9 个状态机缺陷，并把验证从零散探针升级为四层自动化。

## 新能力（用户可感知）

| 能力 | 版本 | 为什么值得存在 |
|---|---|---|
| 从侧栏把会话放进分屏（行悬停按钮 + 行菜单） | 0.1.29 | 不用离开分屏就能加对话；空格优先、其次新增格、满格才替换聚焦格 |
| 注意力跳转 `Mod+Alt+J` + 可点击状态点 | 0.1.29 / 0.1.34 | 只跳「等待回答 / 完成未读」，**运行中不算**（口径已定案） |
| 窄窗切换器显示每格状态 | 0.1.33 | 窄窗只剩一格可见时，其余格的状态不再隐形 |
| 侧栏分屏图标带注意力徽标 | 0.1.38 | 不打开分屏也知道有事 |
| 命名保存布局 + 名字不被覆盖 | 0.1.30 | 长标题自动名难扫；手写名优先 |
| 布局库去重（按编排签名） | 0.1.31 | 交换两格不再产生近似重复条目 |
| 顶栏显示当前布局名 | 0.1.54 | 恢复布局后能一眼知道"在哪套里" |
| `Mod+Alt+S` 键盘交换 | 0.1.32 | 之前交换只有鼠标拖拽 |
| 分割线 `Shift` 5% / `Home`·`Enter` 复位 | 0.1.29 | 宽布局快速调整与还原 |
| 缩格保住正在看的那一格 | 0.1.45 | 缩格本意是专注，不该丢掉被专注的对话 |
| 首次运行与"无匹配"两种空状态文案 | 0.1.51 | "没有匹配的会话"对没有任何会话的新用户是误导 |

## 修掉的缺陷（都是我自己的或沿用的既有逻辑）

| 版本 | 缺陷 | 类别 |
|---|---|---|
| 0.1.40 | 在正在使用的布局上点 ✕ 删不掉（立刻被重新捕获） | 状态机 |
| 0.1.41 | 保存的 5 格布局被清洗成 1 格（超限时保留左子树） | 数据 |
| 0.1.42 | 归档的会话滞留分屏直到重载；两处不可达代码 | 生命周期 |
| 0.1.43 | 应用旧布局会绑定已删除/归档的会话；且可能把布局条目静默删除 | 数据 |
| 0.1.44 | 切到更小的保存布局后焦点指向不存在的格 ⇒ **全部键盘命令失效** | 可用性 |
| 0.1.46 | 2 格分屏能被删成 1 格，破坏 2..4 不变量 | 不变量 |
| 0.1.47 | 最大化格里的会话被移走后，仍停在空的最大化窗口 | 状态一致性 |
| 0.1.48 | 空窗格可被最大化（全屏选择器遮住一切）；清空最大化格不撤销 | 状态一致性 |
| 0.1.55 | Views 弹层声明 `role="menu"` 却不实现菜单语义 | 可访问性 |

## 验证：四层 + 一层空白

| 层 | 手段 | 规模 | 状态 |
|---|---|---|---|
| 纯逻辑 | 单元测试 | 46 条 | 覆盖 |
| 状态机 | `npm run fuzz`（不变量） | 12,000 步 + 280 次持久化往返 | 零违规 |

| **真实宿主** | 真机 | — | **空白** |

每一道守卫与每一个修复都做过**变异验证**（把修复改坏，确认测试会失败）。这不是形式：变异验证至少推翻过我两次错误（"无条件提升焦点"、"测试断言忽略重复结构"）。

## 需求证据（必须说清楚）

**没有外部需求证据。** npm 下载量的逐日曲线显示：我们到 11-06 之前每天为 **0**，11-07 起出现的三位数恰好对应自己的发版与安装动作；而同类 `dsh-split-workspace` 连续一个月每天 28–58 次，才是"有人在用"的形态。

完整数据、判断标准与三个可选动作见 `docs/POSITIONING.md`。一句话：**工程侧可以逐条举证，需求侧不能声称"独一档"。**

## 明确未验证的部分

逐条操作见 `docs/VERIFY-BY-HAND.md`（44 条，含"发现问题请记录三件事"）。

## 边界（刻意不做）

2–4 格；一格一个会话；格内不新建会话、不做文件预览/diff；不拦截侧栏点击导航；不自动隐藏/冻结非聚焦格。
理由与权衡见 `docs/SCOPE.md`；与竞品的强弱项对照见 `docs/DESIGN.md` §7（已按有据评估重写，删掉了此前对竞品的错误归属）。
