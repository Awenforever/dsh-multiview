## 一条命令看全部

```
npm test              # 77 条测试
npm run check         # 构建 + 29 类守卫
npm run fuzz          # 状态机不变量，12,000 步
npm run fuzz:render   # 渲染层不变量，6,250 状态
npm run prove:guards  # 35 个负向对照：证明守卫会失败
npm run prove:recent  # 11 个变异用例（带自检）
npm run prove:selftest # 证明上面的自检会拒绝假证据
```

需要 Python（打测脚本用）与 Node 22+。

## 已知的坑（都是我自己踩过的）

1. **别用 PowerShell 内联写含中文/反引号的文件**——编码损坏过一次（`·` 变成 `路`）。
2. **变异脚本必须先提交**，再用 `mutation.py` 跑；它会重建、校验还原、拒绝空操作。
3. **假宿主的 effect 语义**：`harness.mjs` 现在按组件实例路径存 hooks、执行 cleanup；改动它时要同时跑 `test/interaction.test.mjs`。
4. **跨语言文档不要凭猜写锚点**——先读一遍中文 README 的表格行。
5. **断言若从初始状态就成立，它什么也没证明**（点芯片那条测试因此改过一次）。
