# 首次运行体验报告

用假宿主驱动真实 bundle，按新用户的实际步骤逐步渲染，记录**每一步屏幕上有什么**。数据由 `.dev/vm/report-first-run.mjs` 生成，可复跑。

## 一、四步走的实际观感

| 步骤 | 屏幕上有什么 | 判断 |
|---|---|---|
| 1. 刚装好，一个会话都没有 | 两个空格，各写「还没有会话，先在左侧新建一个」 | 正确但**同一句话出现两次**；两格独立，可接受，暂不改 |
| 2. 新建了两个会话 | 两个选择器各列出两个会话，带回车可用的搜索框 | 好：不用离开分屏就能选 |
| 3. 把第一个会话放进左格 | 左格变成对话，右格仍是选择器 | 好：一格绑定不影响另一格 |
| 4. 放第二个会话 | 顶栏出现布局名「S1 \| S2」、Views 计数 `1`、每格状态点 | 好：**工作集一形成就被自动记住**，不用手动保存 |

## 二、这轮发现并修掉的真问题：键盘完全不可发现

走完四步后，**界面上没有任何地方提到键盘**。用户摆好了三个对话，却不知道存在：

`Mod+Alt+[` `]`（切格）、`Mod+Alt+J`（跳到需要你的格）、`Mod+Alt+S`（交换）、`Mod+Alt+M`（最大化）、`Mod+Alt+W`（清空格）。

这是键盘优先产品的通病：**能力都在，入口没有**。

### 修法：把提示放在"同一动作的控件"上，不新增任何标签

| 位置 | 改动 |
|---|---|
| 格头 ⤢ 按钮 | 悬停提示 `最大化 · Mod+Alt+M`；**读屏名仍是「最大化」** |
| 格头 ✕ 按钮 | 悬停提示 `清空这一格 · Mod+Alt+W` |
| 状态点 | 悬停提示 `等待你回答 · Mod+Alt+J`——用户看向这里时正是想知道"还有没有别的格在等我" |
| 侧栏分屏图标 | 有格需要你时，提示附带 `Mod+Alt+J`——不打开分屏也知道捷径 |

读屏名保持干净（只说动作，不念组合键），提示只对看得见的人生效。这条区分是有意的：屏幕阅读器用户从宿主的「设置 → 快捷键」里拿键位。

### 还差的两个

`Mod+Alt+[` `]`（切格）与 `Mod+Alt+S`（交换）**没有对应的可见控件**，所以没地方挂提示。挂到哪都是硬凑，暂不做——这正是"明确边界"的一部分。

## 三、复跑方式

```
node .dev/vm/report-first-run.mjs
```

输出示例（第 4 步）：

```
bar view name: [ 'S1  |  S2' ]
tooltip hints: [ 'maximize · Mod+Alt+M', 'remove · Mod+Alt+W', … ]
state        : {"focused":"p2","views":1}
```

## 四、局限

这份报告跑在假宿主上：它验证**文案、结构、提示内容**，不验证真实像素、动画与宿主侧快捷键设置页的显示。
后者需要真机，见 `docs/VERIFY-BY-HAND.md`。
